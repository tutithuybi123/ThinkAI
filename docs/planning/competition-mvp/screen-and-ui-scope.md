# Screen, progression, and visibility scope

> **Status: Historical v1.0 UI-scope planning.** Reuse only compatible supporting ideas; v1.1 behavior and current design references govern.

## Production-quality screens

| Screen | Target | Priority | Why |
|---|---|---|---|
| Home | active goal, Continue, current capability summary, one prior receipt/Memory Return | P1 | turns vertical slice into an application |
| Skill/Challenge path | one active micro-skill and minimal context | P1 | gives challenge-first identity |
| Challenge workspace | problem, first attempt, help, answer/method, state feedback | P0 | core learner action |
| Transfer Quest | visually distinct isolated changed-representation event | P0 | signature interaction |
| Capability Receipt | deliberate success/failure outcome and next action | P0 | visible product difference |
| Progress/history | capability summaries + receipts/events in plain language | P1 | proves durable product loop |
| Audit detail | compact technical provenance for one receipt | P1 | supports competition credibility |
| Profile/settings | demo identity/reset affordance only | P2 | do not create account system for appearance |

Every production-quality screen requires loading, empty, success, failure/retry, and navigation states as applicable. No visible dead button, raw debug panel, default browser UI, fake percentage, or unexplained lock.

## ACTIVE / LOCKED / HIDDEN / REMOVE

| Area | Decision | Rationale |
|---|---|---|
| One Grade-10 micro-skill | ACTIVE | deep enough for one real vertical slice |
| 6–10 pair bank | ACTIVE internally | supports repeatability; not all must be surfaced at once |
| Transfer Quest, Receipt, evidence history | ACTIVE | core identity |
| One seeded Memory Return | ACTIVE, labelled historical | explains longitudinal intent honestly |
| One compact audit view | ACTIVE | credibility without LMS scope |
| Adjacent skills | LOCKED only if a small path clarifies next capability | maximum 2–3; label “coming after validation,” not fake content |
| Other subjects/teacher mode | HIDDEN | no implementation and distracts |
| General chat, freeform diagnosis, personalized path | HIDDEN | contradicts narrow controlled protocol |
| Learning layer/multi-source verification | HIDDEN | cannot know external assistance exposure |
| XP, coins, shop, leaderboard, streaks, pets | REMOVE | decorative and risks help avoidance |
| “Assistance debt” / help penalties | REMOVE | conflicts with data integrity and learner safety |

## Minimum progression personality

Use only three evidence-linked mechanics: a capability path node that becomes verified only after a receipt; a Transfer Quest that changes representation; and a labelled Memory Return. Animation may celebrate a receipt after its conditions are shown. No gamified currency or reward for refusing help.
