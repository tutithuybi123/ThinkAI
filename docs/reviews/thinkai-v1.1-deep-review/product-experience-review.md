# Product experience review

## The growth presentation principle

“Measure evidence internally; present growth externally” is a sound safety principle **only** if the translation never hides uncertainty. Show a student a next meaningful action and capability language; retain a tap-through answer to “what have I actually shown?” Do not show a falsely certain skill badge.

Suggested replacement: **Celebrate verified capability; never reward withholding help.** A hint is an allowed learning tool. Independence is a later condition of a claim, not a moral achievement.

## Loop attack

* **Struggle:** productive only when it is brief, purposeful, and escape-able. Forced blank-page time is friction. Let the learner submit an idea, select “I cannot start,” or use a hint after a short attempt—not a timer.
* **Hint:** current copy risks status anxiety: “two hints” immediately precedes a challenge to make a skill one’s own. Do not weaken badges for help use. Store exposure privately/teacher-facing; display a capability route with multiple legitimate paths.
* **Prove:** potentially empowering if it is a voluntary-looking capstone with a real payoff (exam-ready signal, tool unlocked) and rapid recovery after failure. It is punitive if it appears after every solved item, removes help without explanation, or blocks progress.
* **Remember:** can create return behavior only when it is short, scheduled around a learner goal, and has a clear reason (“keep this tool ready for next week’s test”). It is not retention just because a notification was sent.
* **Level Up:** must mean an explicit evidence threshold over named conditions. Never award it for volume or streak. A level needs reversible language: “confirmed for this skill under these conditions,” not a permanent identity label.

## Form comparison

| Form | Identity/retention | Differentiation | Complexity/data | MVP/demo/competition | Verdict |
|---|---|---|---|---|---|
| A. Challenge app | clear action loop; retention unproven | moderate if trials are audited | low-medium | strong 3-minute demo | **MVP shell** |
| B. Game progression | memorable only with real task mechanics | low if cosmetic | medium | seductive demo, high distraction risk | use only evidence-linked unlocks |
| C. Teacher-connected | authentic goals and task review; repeat use via class | high operational value | medium-high; teacher workflow | strongest validity, slower adoption | pilot wrapper, not full MVP |
| D. AI companion | potential habit | low; chat is commoditized | high privacy/attribution | weak concise demo | reject now |
| E. Verification layer | clearest long-term thesis | high if source-agnostic proof works | very high: external help unobservable | future narrative, not MVP | future only |

## Signature alternatives, ranked

1. **Capability receipt**: after a short challenge, show a compact, auditable receipt: “independent near-transfer, no answer reveal, item family X, date.” It makes the evidence claim concrete.
2. **Transfer Quest**: use a changed representation with an explicit “same tool, new situation” reveal after response. Strong only for curated task pairs.
3. **Memory return**: an old capability reappears as a small required tool in a new goal. Strong future mechanism, not demo proof.
4. **Proof-of-Learning Passport**: portfolio of receipts. Useful teacher/parent artifact, risks dashboard feel.
5. **Intervention duel**: compare two learning moves and later show which supported independent success. Requires study scale; future only.
6. **Hidden prerequisite challenge**: good diagnostic, but risks feeling like surprise testing and cannot be trusted before validation.
7. **AI Assistance Debt**: reject. It morally penalizes help-seeking and creates cheating/hint avoidance.

The recognizable ThinkAI session is not “a quiz after a chat.” It is: **use a concept in a new form; receive a capability receipt that states exactly what was independently demonstrated and what remains unknown.**
